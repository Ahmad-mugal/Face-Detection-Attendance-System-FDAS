# FDAS Student Bulk Import Guide

FDAS can create student profiles from a UTF-8 CSV without requiring face capture during the import. Every imported student starts as **Pending Face Registration** and can use the existing 25-sample enrollment workflow later.

## Download the template

1. Sign in as an Administrator or authorized Operator.
2. Open **Students**.
3. Select **CSV Template**.
4. Save `FDAS_Student_Import_Template.csv` and open it in Excel or another spreadsheet editor.

A repository copy is available at `docs/templates/FDAS_Student_Import_Template.csv`. The application download is generated by the same backend definition used by validation, which prevents header drift.

## Exact columns

| Column | Required | Rule |
| --- | --- | --- |
| `Name` | Yes | 2–150 characters. |
| `Email` | Yes | Valid email, unique in the file and existing student records. |
| `Roll Number` | Yes | 1–80 characters, unique in the file and database; formatting is preserved. |
| `Department` | Yes | Must exactly match an existing FDAS Department name after trimming and case normalization. |
| `Class` | Yes | Must exactly match an existing Class in the supplied Department. |

Do not add, remove, or rename headers. Phone, status, internal IDs, semester, and section are intentionally omitted: imported students begin Active, while semester and section come from the selected existing Class.

Example data row:

```csv
Ali Khan,ali.khan@example.com,CS-2026-001,Computer Science,BSCS Semester 5 - A
```

Remove example data before importing if you added it manually; the downloaded template contains only the header row.

## Department and Class matching

FDAS never creates Departments or Classes from CSV text. A misspelling such as `Computer Sciense` is reported as **Unknown Department**. A Class that exists under another Department is reported as a Department/Class mismatch. Department-scoped Operators may import only their assigned Department; All Departments Operators retain their existing scope.

## Duplicate and security rules

- Duplicate Email or Roll Number values within the file are skipped.
- Existing Email or Roll Number values are skipped, so uploading the same file twice is idempotent.
- Formula-like values beginning with `=`, `+`, `-`, or `@` are rejected to reduce spreadsheet formula-injection risk.
- Files are limited to UTF-8/UTF-8 BOM, `.csv`, 1 MB, and 500 rows.
- FDAS validates the file in memory and does not retain the original upload.

## Saving from Excel

In Excel, choose **File → Save As**, then select **CSV UTF-8 (Comma delimited) (*.csv)**. Keep the exact five headers in the first row.

## Upload, preview, and confirm

1. On **Students**, select **Import Students**.
2. Choose the CSV and select **Validate CSV**. Selecting a file does not write data.
3. Review Total, Valid, Invalid, Duplicate, and Existing counts and every row issue.
4. Optionally download the spreadsheet-safe error report.
5. Select **Import X Valid Students**. FDAS revalidates the original file and writes all valid rows as one transaction. An unexpected insertion failure rolls back the whole batch.

## Face registration after import

An imported row displays **Pending Face Registration**, not Face Ready. Select its **Register Face** camera action whenever the student is available. FDAS reuses the production single-face, continuity-protected 25-image capture and deep-embedding workflow. Staff do not re-enter the student's name, email, roll number, Department, or Class. When readiness rules pass, the row changes to **Face Ready**.
